# 局域网会话与验证

实现使用 Network.framework 的 TCP 与 Bonjour（`_mocha-tabletop._tcp`）。客户端直接连房主手机，没有外部服务器，也没有 MultipeerConnectivity 的 8 人连接上限。房间层最多 12 人；传输层最多保留 24 条非关闭中的连接，额外握手空位用于断线恢复，并受握手超时限制。

## 生命周期

- 初次 TCP 就绪后，客户端提交协议版本、房间 UUID、个人资料及房间专属随机重连凭据。房主验证后把连接绑定到玩家 ID；之后请求从绑定取得身份，不能由请求正文任意指定操作者。
- 同一玩家正确凭据的新连接替换旧连接；先解除旧绑定再发送关闭通知，旧连接断开不会把新连接的玩家标离线。错误凭据不能占用已有席位。
- 断线保留席位与局面，暂停本局。客户端每 3 秒尝试重连；前台恢复不会额外建立第二条进行中的连接。服务器未返回有效快照时也有连接期限，不能只靠 TCP 建连无限等待。
- 大厅主动离开发送 `leave`，删除席位；比赛中主动离开保留席位并标离线，可再加入恢复。房主可返回大厅后移除离线玩家。
- 房主结束房间、移除玩家或替换连接时，先发送最终消息与 TCP FIN，等待对端结束或短暂排空期限，而不是发完立即 `cancel()`。新房间可以开始，旧连接排空期间不再向新会话派发消息。

## 限制与防护

- TCP 就绪后 10 秒未通过应用握手则关闭；客户端 12 秒未收到有效初始快照则关闭。
- 心跳每 5 秒，25 秒没有完整消息则关闭。采用单调时钟；不断发送零碎字节不能延长不完整帧的生命周期。
- 长度前缀 JSON 帧限制为 1 MiB；非法帧关闭连接。公开房间列表按 UUID 去重；Bonjour 服务名按 UTF-8 字节截断。
- 凭据按房间分别随机生成并保存在本地。同一房主得到的凭据不能直接用来冒充玩家加入另一个房间。
- 此版本没有 TLS、房主公钥校验或房间密码。它面向可信朋友的局域网，不抵御同网段主动窃听或伪造 Bonjour 房主。连接绑定不等于加密认证。
- LANTransport 和 TableStore 的入口由主队列调用；Network.framework 回调也派发到主队列，房主状态串行更新。

## 已覆盖的自动验证

```sh
./scripts/test.sh --filter LANIntegrationTests
```

测试使用真实 Network.framework TCP 套接字和真实 Bonjour，不是模拟传输：

1. 一名房主和 11 名客户端实际连接并开始 12 人狼人杀，各收到个人投影；第 13 人被拒绝。
2. 大厅正常离开移除成员；房主关闭通知先于 EOF 抵达，客户端不误启动重连。
3. 比赛断线暂停、自动重连、保留原手牌，前台重复回调不产生重复连接。
4. 未绑定请求、错误房间与错误重连凭据被拒绝。
5. 正确凭据在线替换旧连接不把席位标离线。
6. 主机握手期限、客户端初始快照期限，以及不完整帧滴流期限。
7. Bonjour 能发现本机发布的房间，并通过服务端点完成消息往返。
8. 同房间凭据稳定、跨房间凭据不同。
9. 连续 32 条普通消息后，最后关闭消息仍按序收到。

这些结果只证明 macOS 上的真实回环 TCP 和本机 Bonjour 互通。iPhone 真机同 Wi-Fi、个人热点、本地网络授权、锁屏/后台切换、Wi-Fi 隔离及 TestFlight 分发仍需分别实测。
