# 宝石商人

2–4 人基础版，房主主持规则计算。房间座位顺序也是回合顺序，房主先手。发展牌采用自行设计的中文矿场、商路、工坊名称与系统符号；不包含商业插画。

## 已实现

- 90 张发展牌（一级 40、二级 30、三级 20），10 位贵族；每级亮 4 张，贵族为人数 +1。
- 2/3/4 人每色 4/5/7 枚宝石，黄金始终 5 枚。
- 每回合四选一：拿不同颜色、拿同色两枚、预留、购买。拿两枚要求供应至少四枚；拿不同颜色时最多三种，供应不足才减少。
- 明牌预留或盲抽任意级牌堆；最多三张，黄金用尽仍可预留。离开市场的牌立即补齐，牌堆耗尽则不补。
- 永久奖励折扣、免费购买、黄金万能支付；默认优先彩色宝石，也可自行选筹码，主动用黄金替代已有颜色。
- 行动后筹码超过 10 枚时暂停回合，必须手动归还指定数量，可以归还刚拿到的筹码，黄金计入总数。
- 贵族自动到访；同时满足多位时必须选一位，每回合最多一位。
- 回合结束达到 15 分后完成当轮，所有人回合数相同。总分较高者胜；同分看较少的发展牌，再相同则共享胜利。
- 对手的预留牌与牌堆次序不出现在其视图。公开显示筹码、永久奖励、声望、发展牌和预留数量。
- 非当前玩家、重复选项、未知卡牌、非法支付、过时操作均拒绝且不改状态。

仅在没有任何合法行动的极端状态下提供强制跳过，避免局面卡死；正常行动不允许主动跳过。未实现扩展包。

## 动作接口

`take_distinct` 的 values 为颜色 ID；`take_pair` 为一个颜色 ID。`reserve` 为市场卡牌 ID 或 `deck:1` / `deck:2` / `deck:3`。`buy` 选择牌后进入支付步骤：`pay_auto` 无参数；`pay_custom` 选择具体筹码 ID（例如 `white:0`、`gold:0`），同色筹码是不同选项；`cancel_buy` 返回行动选择。`discard` 使用同一筹码 ID 方式；`noble` 选择贵族 ID。

所有合法选择由 `view(for:)` 内的 `ActionPrompt` 返回，不应在 UI 重建合法动作。跨网络只传玩家的投影，不发送引擎状态或 seed。

## 核对来源

- [出版方官方规则](https://cdn.svc.asmodee.net/production-spacecowboys/uploads/2025/10/SCSPL01EN_SPLENDOR_RULES_LIGHT.pdf)：配置、行动、黄金自选支付、贵族及回合结束规则。
- [实物照片及数值转录](https://github.com/anicolao/splendor)：90 张牌的数字成本、等级、颜色、声望事实。使用 `data/verified_card_properties.csv`，未使用照片或插画。
- [独立数值记录](https://github.com/bouk/splendimax/blob/master/Splendor%20Cards.csv)：与上述 90 张牌的数值集合完全一致，已程序比对。贵族采用基础版的五种相邻双色 4+4 及五种连续三色 3+3+3 要求。

## 验证

`GemsTests.swift` 覆盖配置、非法操作原子性、供应阈值、盲抽隐私、预留上限、市场补牌、强制归还、折扣与自动黄金、自选黄金支付、取消与免费购买、贵族选择、最后一轮、两级平分规则，以及 2/3/4 人完整自动对局中的牌和筹码守恒。
