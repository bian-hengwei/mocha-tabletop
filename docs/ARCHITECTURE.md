# 实现说明

## 游戏与玩家视图

`src/core/games/` 中的规则模块使用可序列化状态，负责初始化、校验并应用指令，以及生成玩家视图。非法指令不能部分修改状态。测试覆盖筹码与卡牌守恒、流程推进、胜负结算和隐藏信息。

云端模式由 Worker 持有完整状态，只发送对应玩家的视图；牌堆、他人手牌和秘密身份不能依靠前端隐藏。局域网模式由房主持有完整状态，经 WebRTC 向各玩家分发过滤后的视图，因此房主设备属于信任边界。房间码本身不是身份凭据：玩家通过房间凭据恢复身份，通过邀请链接或房主批准加入。

## 观战席

房间将 `players` 和 `spectators` 分开保存。默认允许最多 20 位观众，不占游戏人数，不参与准备、操作版本或断线暂停判定。房主在准备室和对局中都能通过观战席入口管理开关；关闭时移出观众、撤销凭据并清理观战申请。旧房间缺少这些字段时按允许观战、空观众列表读取。

开局后，新成员通过链接或房间号加入会自动进入观战席；原玩家凭原凭据恢复原座位。开局前可选择观战或在玩家席、观战席之间切换，房主保留玩家/法官席。邀请链接直接加入，只有房间号时仍需房主批准；开局时未处理的玩家申请转为观战申请。观众可随时离开，刷新或短暂断线后可恢复观战；已关闭观战时不能恢复。

云端和 LAN 房主均通过 `viewRoomMatch` 验证成员身份，并调用游戏模块的公开观战投影。观战投影不借用任何玩家视角，不发送手牌、秘密身份、词语/密钥、秘密选牌、暗杠内容或私人核验信息，也不发送游戏操作与私密区块。已经公开的牌面、表决及结算按各游戏原有公开时机展示。所有玩家都能查看观众昵称、头像和连接状态；观战不计入个人战绩。

## 连接与恢复

- **云端**：WebSocket 连接 Durable Object，由 `GameRoom` 校验操作并保存房间状态。
- **局域网**：Worker 提供发现和信令，玩家通过 WebRTC DataChannel 连接房主；未配置 STUN / TURN。房主状态以 localStorage 持久保存并兼容旧 sessionStorage；关闭标签页后可恢复未过期且 matchID 匹配的牌局。
- **房间发现**：根据公开网络地址的服务器端散列分组，不扫描 Wi-Fi 名称，也不保证同一热点上的所有设备都能直连。
- **离线试玩**：Service Worker 缓存前端和素材；同屏轮换座位或单人人机运行规则，不提供离线跨设备配对。

已入座玩家的有效活动（含在线心跳）会续期房间，最多每五分钟持久化一次新的六小时期限，并同步到目录和客户端恢复信息；等待批准者及匿名查询不会续期。目录清理过期索引前会向房间核对有效期，补回同步失败的续期信息并保留原网络分组；暂时无法核对时保留索引等待下一次清理。停止活动后，房间会在最后一次续期约六小时内清理，已过期或解散的房间不会重新激活。断线恢复与退出行为的修改应同时检查 `src/net/`、`worker/` 和 `tests/network/`。

切换标签页、切换应用或锁屏可能使浏览器暂停 JavaScript 定时器。服务端不会仅因已认证连接停发心跳而将玩家断开，局域网也不会仅因应用层心跳变慢就销毁已验证的 DataChannel。未认证连接仍有握手超时；真正的 WebSocket / WebRTC 断开会暂停需要该玩家的牌局并保留座位。

回到前台、网络恢复和 `pageshow`（包括浏览器前进/后退恢复）会主动检查连接。云端对仍显示为打开的 WebSocket 发起探测并重新获取本人的权威视图；探测超时会重新连接，无需等待浏览器完成关闭握手。失败重连采用递增间隔，最大 30 秒，持续到成功、主动退出或服务端确认房间不存在。局域网重新打开的访客可以向房主请求重新配对，房主恢复时会重置配对重试次数。

关闭网页不会发送离桌指令。同一浏览器、同一站点重新打开后，会从 localStorage 恢复原玩家凭据；局域网房主同时恢复 matchID 匹配的本地牌局。已入桌设备离线期间可能错过其他玩家续期，因此缓存到期时间之后另保留最多六小时的恢复尝试窗口，由服务端确认房间是否仍有效；这不会延长服务端租期。主动离桌、房间解散或服务端确认过期会清理对应恢复记录。

操作系统可以终止后台网页或底层网络，无法保证物理连接一直存在；恢复依赖房间仍有效、浏览器存储仍在，局域网还需要房主重新在线。Cloudflare 连接生命周期参考 [WebSocket Hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)。

## 本地数据

`mocha-profile` 保存昵称与头像；`mocha-room-session` 保存恢复房间的凭据及有效期；`mocha-host-*` 保存局域网房主状态（含秘密牌局，仅受信任房主可用）；`mocha-practice-v1` 保存同屏试玩与单人人机，兼容缺少 `mode` 的旧试玩存档。`mocha-history-v1` 仅保存本人已接收的结束结果摘要，不保存他人隐藏手牌，按持久 matchID 去重。删除战绩保留去重 ID，避免刷新终局重新写回。因离线未接收到的结束结果无法事后同步。

已知仍待房主批准的入桌申请会记录待审批状态；主动取消时清除该申请的恢复记录，避免刷新后自动重新申请。取消已入座玩家的恢复连接仍保留凭据；旧版未记录审批状态的存档也继续保留。

头像/战绩等存储不跨域或跨设备同步。存储失败会显示提示；清空浏览器数据会移除恢复能力。

## 人机

八款非自由交流游戏支持房间拥有的机器人席位，详见 [人机说明](BOTS.md)。策略位于 `src/core/bots/`，只接收 `GameView`；`src/core/roomBots.ts` 负责席位校验、调度资格与经 `applyMatch` 执行的一步行动。云端持久化待执行版本及时间，局域网使用房主计时器；两端均保持真人断线暂停和原有秘密信息边界。

单机模式由 `src/local/practice.ts` 复用同一规则与人机调度，每次行动通过 `applyMatch` 校验。单人人机固定第一席为真人，其余席位共用所选难度，UI 不提供换座。前端计时器在退出或换局时清理，旧局的回调不能修改新局；存档保留局号、人数、难度和规则。单人人机战绩使用 `solo` 模式，不计入联机胜负统计。
