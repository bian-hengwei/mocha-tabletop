# 实现说明

## 游戏与玩家视图

`src/core/games/` 中的规则模块使用可序列化状态，负责初始化、校验并应用指令，以及生成玩家视图。非法指令不能部分修改状态。测试覆盖筹码与卡牌守恒、流程推进、胜负结算和隐藏信息。

云端模式由 Worker 持有完整状态，只发送对应玩家的视图；牌堆、他人手牌和秘密身份不能依靠前端隐藏。局域网模式由房主持有完整状态，经 WebRTC 向各玩家分发过滤后的视图，因此房主设备属于信任边界。房间码本身不是身份凭据：玩家通过房间凭据恢复身份，通过邀请链接或房主批准加入。

## 连接与恢复

- **云端**：WebSocket 连接 Durable Object，由 `GameRoom` 校验操作并保存房间状态。
- **局域网**：Worker 提供发现和信令，玩家通过 WebRTC DataChannel 连接房主；未配置 STUN / TURN。房主同标签页刷新可从 sessionStorage 恢复，关闭标签页可能丢失局域网房间。
- **房间发现**：根据公开网络地址的服务器端散列分组，不扫描 Wi-Fi 名称，也不保证同一热点上的所有设备都能直连。
- **离线试玩**：Service Worker 缓存前端和素材；同屏轮换座位运行规则，不提供离线跨设备配对。

房间有过期清理机制。断线恢复与退出行为的修改应同时检查 `src/net/`、`worker/` 和 `tests/network/`。

## 规则范围

| 游戏 | 当前实现 |
| --- | --- |
| 宝石商人 | 基础版 90 张发展卡、10 张贵族；预留公开市场任意层级的一张牌，或盲抽某层牌堆顶牌；最多预留 3 张。公开预留保持公开，盲抽只显示给持有者。 |
| 炸弹猫 | 基础版玩法：拆弹、攻击、跳过、索取、洗牌、预知、否决及两张/三张组合。否决窗口由所有存活玩家确认，避免暴露谁持有否决牌。不含扩展牌和五张弃牌组合。 |
| 狼人杀 | 标准模式采用预言家、女巫、猎人、守卫与屠边规则，人数决定角色配置；女巫不能自救、守救同人会死、中毒猎人不能开枪。法官模式由法官控制流程；仅发身份模式由线下主持约定后续规则。 |
| 阿瓦隆 | 组队投票、秘密任务票、连续五次否决判负、梅林刺杀；7 人及以上的第 4 次任务需要两张失败票。 |

规则依据：[Splendor 官方规则](https://cdn.svc.asmodee.net/production-spacecowboys/uploads/2025/10/SCSPL01EN_SPLENDOR_RULES_LIGHT.pdf)、[Exploding Kittens 官方规则](https://www.explodingkittens.com/pages/rules-kittens)、[Avalon 出版方](https://indieboardsandcards.com/our-games/the-resistance-avalon/)。狼人杀存在不同桌规，以本项目界面和上述实现为准。
